The eight requirements as acceptance tests

Read each test, then read what the repository does. The gap between them is the work. Every verdict is linked to the file it was measured in.

Each requirement of the brief is restated as a test the repository either passes or fails. A requirement is MET only when its acceptance test passes on published data; PARTIAL when part of it passes; NOT MET when nothing satisfies it; BLOCKED when it cannot be satisfied without a decision or a purchase. Verdicts come from reading the files, not from intent.

R1 Price-snapshot store that records opening and closing numbers for every market we originate PARTIAL

Without both ends of the price, closing-line value cannot be measured, and without closing-line value a hit rate is not evidence of skill.

Acceptance test. For every originated market there is one row per book carrying market_id, book, open_price, open_timestamp, close_price, close_timestamp, price_format and source_url. A market cannot be graded unless open and close are both present.

Status. Store is live with schema origin-snapshots-v1, append-only by (market_id, phase): 39 open rows RECORDED, 39 close rows PENDING. Every market_line is blank, so no closing-line value can be computed yet.

Owner. origin/data/snapshots.json (session arena/f2df8317-x3, merged in PR #47)

Blocker. No price provider. The store is waiting on a data-rights decision, not on code. See Q01 and S01.

Evidence. repo artifact - schema live, prices blank

R2 Verified results feed so backtests and ROI can be computed at all PARTIAL

ROI is (settled return - stake) / stake. Every term needs a settled result, so without a results feed no leaderboard row can be scored.

Acceptance test. One row per completed game with final score for both clubs, the official source URL, the retrieval timestamp, and a written settlement rule per market type (side, total, moneyline) including how ties and pushes are treated.

Status. The feed exists and backtests now run on it: origin/data/results.json holds 163 games / 137 finals with a per-row official URL, cross-checked 163/163 against the desk game log, and a walk-forward backtest is published per week. ROI still cannot be computed, and no settlement rule is written down.

Owner. origin/data/results.json and origin/data/backtest.json (session arena/f2df8317-x3, merged in PR #47); data/desk/games.json (session arena/3bf7cc8b-x3)

Blocker. No settlement rule, and no player-prop results. See Q04, S02, S09.

Evidence. repo artifact - transcription of official week pages

R3 Originate the side first, then the total, then the moneyline MET

The moneyline is a function of the expected margin and its uncertainty. Deriving it last keeps the three markets mutually consistent; deriving them independently produces arbitrage against yourself.

Acceptance test. Each game carries three originated rows in the order side, total, moneyline. The moneyline row records the margin and the sigma it was derived from, so it is reproducible.

Status. 39 originated rows, 13 games x 3 market types, with seq order side then total then moneyline. This session re-checked the order for all 13 games: 0 violations. The moneyline records its own derivation - P(home win) = Phi(adj_margin / 13.5) on the side's adjusted margin - so it is reproducible from the side.

Owner. origin/data/markets.json (session arena/f2df8317-x3, merged in PR #47)

Blocker. None. The order requirement is satisfied.

Evidence. repo artifact - order verified 0 violations of 13

R4 Publish the model's fair line, the market line, and the difference as separate columns PARTIAL

The difference is the whole signal. Publishing only a fair line leaves the reader to do the subtraction against a price they cannot see.

Acceptance test. Three distinct columns per market: fair_line, market_line, and edge = fair_line - market_line, each with its own units label and sign convention.

Status. The column contract exists: fair_line, market_line and diff are three separate fields on all 39 rows, each with a unit label and a recorded sign convention. fair_line is populated for every market. market_line and diff are blank in all 39 rows because no source publishes a price.

Owner. origin/data/markets.json (session arena/f2df8317-x3, merged in PR #47)

Blocker. Depends on R1. No official source publishes NFL prices. See Q01 and S01.

Evidence. repo artifact - columns present, market and diff blank

R5 Separate 'signal' from 'staking' in the leaderboard so a lucky staking run cannot mask a bad signal PARTIAL

A flat-stake record measures whether the fair line was right. A sized record mixes that with how much was risked. Ranking on the blend lets a Kelly run on coin-flips outrank a real edge.

Acceptance test. Every leaderboard row carries two independently computed scores: a signal score that is stake-independent (mean closing-line value per bet, with n and a 95% CI) and a staking score that is PnL-dependent (ROI, drawdown, units). A strategy must be able to rank top-decile on signal while flat on staking, and the board must show both columns.

Status. The separation is implemented in the data rather than only described: every leaderboard row carries a signal block (metric, value, n, rank) and a separate staking block. The signal half is populated - side winner-direction accuracy 0.595 (n = 121), total over/under hit rate 0.4957 (n = 117), moneyline Brier 0.2373 (n = 121). The staking half is blocked with 0 settled bets.

Owner. origin/data/leaderboard.json (session arena/f2df8317-x3, merged in PR #47)

Blocker. The staking half needs prices and a settlement rule. See Q01, Q04, S05.

Evidence. repo artifact - signal populated, staking blocked

R6 Track the depth of the replacement, not just the fact of a replacement PARTIAL

'Starter out' and 'third-string guard starting' are different events with different expected effects. Counting only the fact treats them as identical and throws away the signal.

Acceptance test. For each absent starter: the ordinal depth of the replacement (1st, 2nd, 3rd, 4th string or undrafted/free-agent pickup), the club chart URL, and the chart's as-of date. A row without an as-of date is published as unverified, not as fact.

Status. An ordinal is now recorded, not just a name: replacement_ordinal is populated for 42 of 76 Week 10 absences, with a reason_if_blank field explaining each gap. Zero of 76 rows carry a chart as-of date, and the club charts are self-labelled unofficial by the clubs that publish them.

Owner. origin/data/depth.json (session arena/f2df8317-x3, merged in PR #47); data/desk/deficiencies.json (session arena/3bf7cc8b-x3)

Blocker. No chart carries a date, so an ordinal cannot be tied to a point in time. See Q06, S06, S07, and flag C-12 for a count discrepancy between the two trees.

Evidence. repo artifact - club charts, no as-of date

R7 Compute correlations only from officially sourced numbers and publish n with each value MET

A correlation is the input to the parlay leg screen. An r with no n is unfalsifiable, and an r computed on unlogged data is a guess dressed as a measurement.

Acceptance test. Every published coefficient carries n, the official source URL, a 95% CI, and a plain reading. A coefficient whose CI contains 0 is labelled 'not distinguishable from no relationship' and is not used to price anything.

Status. Every coefficient carries n, a 95% interval, and the official source URL, and the mislabelled pair has been republished correctly: game total vs |home margin| is now -0.0157 and signed home margin vs total is -0.1607, as two separate rows. The older desk copy still carries the wrong label - see flag C-01.

Owner. origin/data/correlations.json (session arena/f2df8317-x3, merged in PR #47); data/desk/correlations.json (stale copy)

Blocker. None. See flag C-01 for the stale copy still published on another tree.

Evidence. repo artifact - n and CI published with every value

R8 Define a demotion gate that sends a live strategy back to paper MET

A promotion gate with no demotion gate is a one-way door: a strategy that was lucky once stays live forever. The demotion rule is what makes the promotion rule mean anything.

Acceptance test. A written rule with numeric thresholds, a look-back window, and an automatic action: for example, return to paper when the rolling 200-bet closing-line value is negative, or when the 95% CI on ROI contains zero over the last 200 graded bets, or on any data provenance failure. Every demotion is logged with its trigger.

Status. Gate D-1 is written with five numeric triggers and an automatic action: rolling median closing-line value of the last 20 settled bets <= 0 twice in a row (D-1a); drawdown from peak >= 25% (D-1b); signal below 50% for three consecutive cycles (D-1c); any data-integrity failure (D-1d); any unregistered model change (D-1e). D-1d and D-1e are armed now; D-1a to D-1c arm at promotion. D-2 defines re-promotion.

Owner. origin/data/gates.json (session arena/f2df8317-x3, merged in PR #47)

Blocker. None on the rule. Enforcement is still manual - see Q14 and S04.

Evidence. repo artifact - D-1 triggers and D-2 re-promotion
