How to review

Read the Problem and the Paths, then record a decision. A path that is not chosen is still a documented option; the reason for rejection is as valuable as the reason for acceptance.

S-001 Make the verification ledger a hard gate on every published number P0 Verification & Trust adopted

Problem. A decision-support platform is only trusted if every number can be traced. Today the trace exists in the manifest but it is not visible at the point of use, so a reader cannot tell an official figure from a derived one without opening the repository.

Proposed change. Render the source URL, the fetch timestamp and the payload hash directly in the table rows, and make the CI validator refuse to build if any dataset row lacks a source link.

Expected impact. Removes the largest single trust risk: a reader can act on any published figure without leaving the page.

Decision paths

Path A Row-level source links plus a CI gate (recommended)recommended

Every row carries an 'Official source' cell linking to the exact page it was read from; the validator fails the build on any row without one. The hash and timestamp stay on the Sources page.

  • Cheapest to build and already proven by the current validator.
  • Matches the brief's requirement that every table row has a source link.
  • Does not clutter the wide data tables.
  • Hash and timestamp are one click away rather than inline.
Cost Low - validator and renderer already exist.Effort Days, not weeks.Risk LowReversible Fully

Path B Inline provenance on every cell

Each individual value is stamped with its source, timestamp and hash.

  • Maximum auditability at the point of use.
  • Tables become unreadable on a dashboard.
  • Large performance and maintenance cost for little decision value.
Cost HighEffort Weeks.Risk Low technical risk, high usability risk.Reversible Fully

Path C Publish a separate audit appendix

Keep the dashboard clean and put all provenance in an appendix document.

  • Cleanest reading experience.
  • Breaks the brief's requirement that each row has a source link.
Cost MediumEffort Days.Risk Does not satisfy the stated requirement.Reversible Fully

Recommendation

Path A satisfies the brief literally, keeps the dashboard readable and reuses machinery that already exists. Path B solves a problem the reader does not have.

Evidence
  • The brief requires that every table row have a source link to an official site, and that values which cannot be confirmed are left blank and flagged.
S-002 Separate the line model from the evaluation reference to break circularity P0 Model Design proposed

Problem. The platform originates its own lines. If a strategy is then scored against those same lines, the evaluation measures self-consistency rather than skill: any strategy that agrees with the line model looks correct by construction. This is the single most dangerous methodological trap in the brief.

Proposed change. Introduce an explicit separation between the Line Model that prices games and an Evaluation Reference that scores strategies, with the two built on disjoint feature sets and disjoint time windows.

Expected impact. Turns the leaderboard from a measure of agreement with our own model into a defensible skill ranking.

Dependencies. Q-010Q-009Q-027

Decision paths

Path A Two-model separation with a held-out evaluator (recommended)recommended

The line model uses team strength, scoring efficiency and availability. The evaluator is a separately specified model, trained on a disjoint period and a different feature set, that produces a reference probability used only for scoring.

  • Breaks the circularity without introducing any third-party data.
  • Stays entirely within the 'originate our own lines' requirement.
  • Makes the claim of skill testable against something that was not built to agree with the strategy.
  • Two models to maintain and two sets of parameters to version.
  • The evaluator can itself be overfitted; it needs its own gates.
Cost Medium - both models already share the same data pipeline.Effort Weeks.Risk Medium - mitigated by applying the same validation discipline to the evaluator.Reversible Fully

Path B Permit an independent market reference for evaluation only

Continue to originate every published line, but allow the evaluation harness to compare against a consensus closing price that is never ingested by the line model.

  • The strongest available test of skill, because the reference is external and independent.
  • Directly measures the standard the industry uses (closing line value).
  • Requires a licence or a data source for consensus lines that the official-only rule does not currently allow.
  • Depends on the answer to Q-001 and Q-002 on whether commercial activity is in scope at all.
Cost Medium to high, depending on the data source.Effort Weeks.Risk Legal and data-licensing risk, therefore blocked on Q-001/Q-002.Reversible Fully

Path C Score only against a pre-registered null model

Require each strategy to beat a null (no-skill) baseline with a pre-registered significance threshold, and abandon any claim that the ranking measures market-relative skill.

  • Needs no second model and no external data.
  • Simple to explain and to audit.
  • Only proves the strategy is better than nothing, not that it is better than a well-built price.
  • Produces a leaderboard whose absolute level is unanchored.
Cost LowEffort Days.Risk Medium - the leaderboard would overstate what it measures.Reversible Fully

Recommendation

Path A is the only option that satisfies the owner's requirement to originate our own lines while still producing an honest skill measurement. Path B is stronger in principle but is blocked on the legal questions. Path C is an honest floor, not a destination.

Evidence
  • The line model must originate its own lines from official data rather than consuming a commercial feed.
S-003 Adopt walk-forward validation with purging and embargo instead of a single train/test split P0 Model Design proposed

Problem. NFL seasons are short and heavily autocorrelated. A random train/test split leaks information across adjacent games, which inflates measured edge and is one of the main reasons a back-tested strategy fails live.

Proposed change. Replace the random split with anchored walk-forward evaluation: train on all data up to a cut point, evaluate on the next block, roll the cut point forward, and purge plus embargo games near each boundary that share a team.

Expected impact. Measured edge falls closer to true edge, which is the point: fewer strategies qualify, but those that do are real.

Dependencies. Q-004Q-008

Decision paths

Path A Anchored walk-forward with purge and embargo (recommended)recommended

Expanding-window walk-forward evaluation. Around each boundary, remove training games for teams that also appear in the evaluation block (purge) and add a short buffer (embargo) so that features with slow decay, such as rolling scoring averages, cannot bridge the split.

  • Matches how the strategy would actually be used.
  • Removes the dominant source of optimistic back-test results.
  • Produces a natural record of how the strategy would have performed in each period.
  • Produces fewer evaluation observations than a random split.
  • Requires more seasons of history to reach a stable estimate.
Cost Low - a scheduling change in the harness.Effort Days.Risk Low.Reversible Fully

Path B Keep a random split but add multiple seeds

Average over many random splits to reduce variance in the reported metric.

  • Simple.
  • Produces many more evaluation observations.
  • Averages the leakage rather than removing it; the bias survives the averaging.
  • Cannot be defended to a reviewer who understands leakage.
Cost LowEffort Days.Risk Medium - retains the bias this suggestion exists to remove.Reversible Fully

Path C Nested cross-validation with an inner optimisation loop

Use an outer loop for evaluation and an inner loop for hyper-parameter selection.

  • Controls for hyper-parameter overfitting, which walk-forward alone does not.
  • The most rigorous option available.
  • Expensive to run and to explain to a non-technical reviewer.
  • Given the small number of seasons, the outer folds are still few.
Cost MediumEffort Weeks.Risk Low technically, high communication cost.Reversible Fully

Recommendation

Path A is the standard remedy for time-series leakage and is cheap. Path C is stronger but its cost/benefit is poor at this sample size; it can be revisited if the history depth question (Q-004) is answered generously.

S-004 Keep a register of every hypothesis tested, including the failures P0 Model Design proposed

Problem. A strategy found by testing many variants will look excellent in-sample even when it has no edge. If only the winners are published, a reader cannot tell selection from skill.

Proposed change. Maintain a hypothesis register in the repository. Every tested hypothesis is recorded whether it passed or failed, with its measured result, and a false-discovery-rate control is applied across the register before any strategy is declared eligible.

Expected impact. The leaderboard becomes defensible: a reader can inspect how many ideas were tried and how many survived.

Dependencies. Q-015Q-008

Decision paths

Path A Full hypothesis register with false-discovery-rate control (recommended)recommended

A committed register of tested hypotheses and their measured results, with a Benjamini-Hochberg control across the family of tests performed in a cycle.

  • Makes selection bias visible rather than hiding it.
  • Standard practice in a research context and easy to defend.
  • Also functions as a record of dead ends, which stops the team re-testing them.
  • Requires discipline: every experiment must be logged, including the ones run and abandoned.
  • Publishing failures can be uncomfortable, but that is the point.
Cost Low to mediumEffort Days, ongoing.Risk Low.Reversible Fully

Path B Publish only the winner plus its rejection criteria

State the gates in advance and publish only strategies that passed.

  • Much less operational discipline required.
  • The reader still sees the acceptance bar.
  • The reader cannot tell how many hypotheses were tried, so the multiple-testing problem is invisible.
  • Pre-registration alone does not bound selection bias if the pre-registration is not enforced.
Cost LowEffort Days.Risk Medium - leaves the central bias unaddressed.Reversible Fully

Recommendation

Only path A makes the selection process auditable, which is a precondition for calling a leaderboard a skill ranking rather than a lucky-moment ranking.

S-005 Publish an explicit skill-share metric that separates model-implied variance from residual variance P0 Measurement proposed

Problem. The brief asks to remove luck from the equation. A win rate or an ROI cannot do that: a strategy that wins 55 per cent of its bets by luck looks identical to one that wins 55 per cent through skill until the sample is large enough to tell.

Proposed change. For each strategy compute a skill share: the proportion of observed outcome variance that is explained by the model's own probability (model-implied variance divided by total observed variance), report the residual share as the luck component, and attach a bootstrap confidence interval so that a strategy whose interval includes zero skill is visibly not proven.

Expected impact. Makes the luck-versus-skill question answerable per strategy and gives the leaderboard a defensible eligibility rule.

Dependencies. Q-009Q-008

Decision paths

Path A Variance decomposition with bootstrap intervals (recommended)recommended

For each bet the model implies a win probability; the binomial variance implied by those probabilities is the model-explained component, and the remainder is residual. The ratio is reported with a bootstrap interval and with the permutation-test p-value for a pure-luck null.

  • Directly answers the brief: it quantifies how much of the outcome was skill.
  • Works for any market because it needs only the model's probability and the result.
  • The permutation test gives a clean 'no better than luck' verdict.
  • Depends on the quality of the model's probability, so it inherits the model's error.
  • Intervals are wide at small sample sizes, which is honest but unsatisfying.
Cost Low - a standard computation over existing results.Effort Days.Risk Low.Reversible Fully

Path B Stability-based test instead of variance decomposition

Require the edge to be positive in a majority of independent time blocks and across seasons.

  • Intuitive and easy to explain.
  • Robust to a badly calibrated probability model.
  • A coarse measure: it can pass a lucky strategy that happened to be up in most blocks.
  • It does not quantify how much of the outcome was skill.
Cost LowEffort Days.Risk Medium - weaker than the brief requires.Reversible Fully

Path C Skill measured against the market's implied probability

Compare the strategy's result to the probability implied by the platform's own line.

  • Simple and familiar.
  • Circular: it measures agreement with the line model, not skill. This is exactly the trap described in S-002.
  • Cannot be used until S-002 is resolved.
Cost LowEffort Days.Risk High - methodologically invalid on its own.Reversible Fully

Recommendation

Path A is the only option that produces a quantity that can honestly be called a skill share, which is what the brief asks for. Path B is a useful companion gate, not a substitute.

S-006 Build parlays from a correlation budget rather than from the strongest legs P0 Strategy Design proposed

Problem. Parlay legs that look individually attractive are often driven by the same underlying event, such as a fast pace or a shootout. Multiplying them produces an apparent edge that is really a single bet with a worse price and a fatter tail.

Proposed change. Constrain every parlay by an explicit correlation budget: the legs' pairwise correlations must sum below a limit, the effective number of independent legs must clear a minimum, and the combined implied probability is recomputed from the joint rather than the product of marginals.

Expected impact. Prevents the platform from publishing parlays whose edge is an artefact of multiplied correlated probabilities.

Dependencies. Q-011Q-023

Decision paths

Path A Correlation budget with an effective-independent-legs floor (recommended)recommended

Compute the pairwise correlation matrix of candidate leg signals, reject any parlay whose legs exceed the budget, and re-price the parlay from the joint distribution implied by the correlation structure rather than from the product of marginals.

  • Directly prevents the most common parlay error.
  • Uses correlations the platform has to compute anyway for the leaderboard.
  • Makes the parlay's true probability visible, which the naive product overstates.
  • Reduces the number of eligible parlays, sometimes sharply.
  • Requires a longer history to estimate correlations reliably.
Cost Low to mediumEffort Weeks.Risk Low.Reversible Fully

Path B Simple rule-based leg exclusion

Forbid legs that involve the same game, the same team or the same player.

  • Trivial to implement and explain.
  • Removes the worst cases immediately.
  • Misses subtler correlation between different games, which is the real problem.
  • Gives the appearance of control without the substance.
Cost LowEffort Days.Risk Medium - insufficient for the stated goal.Reversible Fully

Path C Price parlays from a joint model directly

Model the joint outcome distribution across games and price parlays from it, with no separate correlation filter.

  • The most principled pricing approach.
  • Automatically produces the correct probability for any leg combination.
  • Needs a joint model across games, which is a substantial modelling task.
  • Sensitive to model misspecification in a way that is hard to diagnose.
Cost HighEffort Months.Risk Medium.Reversible Fully

Recommendation

Path A delivers the substance of path C at a fraction of the cost, and path B is too weak to satisfy the brief's requirement to determine correlation values.

S-007 Adopt a two-tier data policy: official-verified data is publishable, everything else is quarantined P0 Verification & Trust proposed

Problem. The brief forbids inferring values. In practice some useful quantities cannot be sourced officially. Without a stated policy, the temptation is to fill the cell, and the platform's central promise is lost.

Proposed change. Two tiers. Tier 1 (official-verified) is the only tier that may appear on a decision page or feed a leaderboard row. Tier 2 (derived, estimated or owner-supplied) is stored with its derivation recorded and is visible only in the research appendix, permanently labelled.

Expected impact. Preserves the integrity of the platform while unblocking the research questions that official data alone cannot answer.

Dependencies. Q-018Q-019

Decision paths

Path A Two tiers with hard separation (recommended)recommended

Tier 1 is publishable and feeds the leaderboard. Tier 2 is recorded with its derivation and shown only in the research appendix with an explicit label.

  • Preserves the no-inference promise on every decision surface.
  • Still permits useful research on quantities the NFL does not publish.
  • Makes the boundary auditable: a validator checks that no Tier 2 value appears on a decision page.
  • Some strategies will be limited to Tier 1 inputs and may be weaker.
  • Two storage and rendering paths to maintain.
Cost Low to mediumEffort Days.Risk Low.Reversible Fully

Path B Official-only, full stop

Reject anything that cannot be sourced officially, and accept that some research questions stay closed.

  • The simplest possible rule and the easiest to defend.
  • Closes off legitimate questions, for example depth ordering for clubs without a published chart.
  • Pushes researchers toward inference through the back door.
Cost LowEffort Days.Risk Medium - practical pressure will push the team toward breaches.Reversible Fully

Recommendation

Path A keeps the published promise intact while leaving a legitimate route for research questions, and the validator makes the separation enforceable rather than aspirational.

Evidence
  • The brief states that if a value cannot be confirmed from an official source it must be left blank and flagged, and that values must never be inferred or filled in.
S-008 Treat the injury report as a timestamped snapshot, not a statement of fact P0 Injury & Depth adopted

Problem. The official injury report is a practice-participation record published on a schedule. A player who is not on it is not thereby healthy, and a report read on Saturday may be superseded before kickoff. Treating either as a fact creates silent look-ahead bias and false confidence.

Proposed change. Model each injury entry as a snapshot with an explicit as-of time, publish the age of the snapshot on the page, and add a rule that absence from the report is recorded as 'not reported' rather than 'healthy'.

Expected impact. Makes every injury-driven signal auditable and back-testable on the information actually available at decision time.

Dependencies. Q-007Q-020

Decision paths

Path A Timestamped snapshots with an explicit not-reported state (recommended)recommended

Every injury row carries its source, its report week and the fetch time; the page shows the snapshot age and warns when it exceeds the agreed staleness limit; players outside the report are modelled as not-reported.

  • Removes the most common inference error in injury modelling.
  • Makes back-tests honest about what was knowable at decision time.
  • Simple to implement on top of the existing manifest.
  • Requires historical snapshot retention to back-test properly (Q-007).
  • Users must learn a third state between healthy and injured.
Cost LowEffort Days.Risk Low.Reversible Fully

Path B Infer availability from absence

Treat a player missing from the report as available.

  • Simplest possible data model.
  • Explicitly the inference the brief forbids.
  • Systematically wrong, because clubs list only selected players.
  • Would corrupt every injury-driven signal.
Cost LowEffort Days.Risk High - invalidates the injury signal.Reversible Fully

Recommendation

Path A is the only path consistent with the brief's verification rule, and it also fixes a real look-ahead problem in the back-test.

Evidence
  • The official NFL injury report lists, per team, the players reported for the game with their practice participation and game status. (NFL.com official injury report)
S-009 Resolve replacement depth through a documented fallback chain instead of inference P0 Injury & Depth proposed

Problem. The brief asks the platform to know when a second, third or fourth string backup replaces a starter. Depth ordering is published by clubs, not by the league, in inconsistent formats, and it changes between weeks. Any gap tempts a guess.

Proposed change. A strict, published resolution order for the depth string of a replacement: (1) the club's official depth chart; (2) the official game book, which lists the starters and the order in which substitutes entered; (3) blank, with the item flagged for review. Never infer.

Expected impact. Makes the second, third and fourth string question answerable where official evidence exists and honestly blank where it does not.

Dependencies. Q-006Q-018

Decision paths

Path A Three-step official fallback chain (recommended)recommended

Try the official club depth chart, then the official game book starters and substitution order, then leave the cell blank and flag it.

  • Uses only official sources at every step.
  • The substitution order in the game book is a genuine official signal of who is the second and third string at a position.
  • Gaps stay visible instead of being quietly filled.
  • Will not resolve every club in every week, so coverage will be partial.
  • Substitution order reflects who the coaches chose to use, which is not identical to the chart.
Cost Low to mediumEffort Weeks.Risk Low.Reversible Fully

Path B Club depth charts only

Use the club's own depth chart and flag everything else.

  • Simple and consistent.
  • Exactly the position ordering the club publishes.
  • Leaves a large share of the league unresolved.
  • Some club charts are dated or omit positions entirely.
Cost LowEffort Days.Risk Medium - coverage will be too thin to support the requirement.Reversible Fully

Path C Add a manually curated depth table

Maintain a hand-built depth table in the repository.

  • Complete coverage and human judgement.
  • Can express nuance that a chart cannot.
  • A hand-built table is an unauditable, inferential input - exactly what the brief forbids.
  • It will be stale within a week and will drift silently.
Cost High ongoingEffort Ongoing manual work.Risk High - directly contradicts the verification rule.Reversible Fully

Recommendation

Path A is the only path that satisfies the requirement while keeping every input official and auditable. Path C would look more complete while destroying the platform's central guarantee.

Evidence
  • Official club sites publish their own depth charts; the pipeline probes all 32 club domains and records coverage. (NFL.com team index)
S-010 Score the leaderboard on risk-adjusted, sample-gated metrics instead of raw profit P0 Competition proposed

Problem. A leaderboard ranked on profit rewards whichever strategy took the most risk or got the luckiest run. The brief asks for a competition that rewards the best strategies, not the luckiest outcomes.

Proposed change. A composite score built from risk-adjusted return, drawdown, sign consistency across time blocks and skill share, with hard eligibility gates applied before scoring. Reward tiers are assigned from the composite, with ties broken by a published rule.

Expected impact. Turns the leaderboard from a luck ranking into a skill ranking that can carry rewards.

Dependencies. Q-008Q-009Q-011Q-013

Decision paths

Path A Gated composite score (recommended)recommended

A strategy must clear every gate to be scored at all. Eligible strategies are ranked by a composite of risk-adjusted return, maximum drawdown, block-wise sign consistency and skill share, each normalised and weighted. Ties are broken by the higher skill share, then by the earlier registration date.

  • Rewards quality rather than luck or risk-taking.
  • The gates make the ranking interpretable: each component is visible.
  • The published tie-break removes arbitrary outcomes.
  • The weights are a judgement call and must be published and versioned.
  • A composite can hide a weak component behind a strong one, so components are also shown separately.
Cost LowEffort Days.Risk Low.Reversible Fully

Path B Rank on return on capital with a drawdown cap

Rank on profit divided by capital staked, subject to a maximum drawdown limit.

  • Very simple to explain to any participant.
  • Still rewards a lucky run during any finite sample.
  • The drawdown cap is enforced by refusing trades rather than by measuring skill.
Cost LowEffort Days.Risk Medium.Reversible Fully

Path C Rank on out-of-sample performance only

Score only the live, forward portion of each strategy's record.

  • The cleanest possible definition of skill, with no back-test contamination.
  • Needs a long live period before any ranking is meaningful.
  • Unsuitable for a competition that needs an early result.
Cost LowEffort Days, plus waiting.Risk Low technically, but the competition cannot launch meaningfully.Reversible Fully

Recommendation

Path A gives an immediately usable leaderboard while enforcing the gate discipline the brief requires. Path C should still run in parallel as the final arbiter once enough live data exists.

S-011 Publish a stake and bankroll policy with capped fractional sizing P1 Model Design proposed

Problem. A skilled strategy with unbounded sizing fails for reasons unrelated to skill, and the leaderboard's drawdown numbers are meaningless without a stated stake policy.

Proposed change. Define a stake policy: a fixed fractional stake per bet, a hard per-bet cap, a reduction rule for parlays with more legs, and a bankroll definition used for all normalised metrics.

Expected impact. Makes drawdown, return and the skill-share metric comparable across strategies and reproducible by a third party.

Dependencies. Q-012Q-010

Decision paths

Path A Fixed fraction with per-bet caps (recommended)recommended

A fixed fraction of the bankroll per bet, scaled down as the number of parlay legs rises, with a hard cap per bet and a minimum bankroll stated for the metrics to be meaningful.

  • Makes every published metric comparable and reproducible.
  • Protects a skilled strategy from ruin.
  • Simple to state and to audit.
  • A fixed fraction is not optimal for every probability, so it forgoes some growth.
  • It makes the metrics slightly less flattering than Kelly sizing.
Cost LowEffort Days.Risk Low.Reversible Fully

Path B Fractional Kelly

Bet a fixed fraction, for example a quarter, of the Kelly-optimal stake implied by the model's probability.

  • Theoretically strong growth; directly rewards a well-calibrated model.
  • Standard practice among serious operators.
  • Depends entirely on the model's probability being calibrated, which is exactly what is in question (S-002).
  • A mis-calibrated model plus Kelly sizing produces the fastest possible ruin.
Cost LowEffort Days.Risk Medium to high until calibration is demonstrated.Reversible Fully

Recommendation

Path A is safe under every model-quality assumption, including the unresolved one about calibration. Kelly sizing can be enabled later, gated on demonstrated calibration.

S-012 Make the line model transparent, versioned and margin-aware P1 Model Design proposed

Problem. A line is only useful if the reader knows what it is made of. A black-box line cannot be audited, cannot be improved in a controlled way, and cannot be checked by the owner.

Proposed change. Publish the line model's inputs, weights, margin and version on the site, keep each published line tagged with the model version that produced it, and never republish a historical line under a new version.

Expected impact. Turns the originated lines from a black box into a reproducible artefact that the owner can check.

Dependencies. Q-025Q-027

Decision paths

Path A Published method card with per-line version tags (recommended)recommended

A method card page describing the model, its inputs, the margin and its version, with every published line carrying the version tag and its source timestamp.

  • Makes the platform's own output auditable, which is the same standard applied to official data.
  • Lets a reviewer reproduce any published line.
  • Enables the change-control rule in S-016.
  • Exposes the method, which makes it easier to copy.
  • Requires discipline that the published method matches the running model.
Cost LowEffort Days.Risk Low.Reversible Fully

Path B Publish the inputs but not the weights

Disclose which data is used and disclose nothing about how it is combined.

  • Keeps the method proprietary.
  • The platform cannot then audit its own output, which is inconsistent with the standard it applies to official data.
  • A reader cannot tell whether a line changed because the data changed or the method changed.
Cost LowEffort Days.Risk Medium.Reversible Fully

Recommendation

Path A applies the platform's own verification standard to the platform's own output. That consistency is worth more than the theoretical advantage of opacity.

S-013 Acquire official per-game player logs so prop strategies can be evaluated at all P0 Data proposed

Problem. Season-level player statistics are sufficient for ranking players but not for evaluating a player-prop strategy, which depends on per-game variance. Without per-game logs the prop and prop-combination classes cannot be back-tested, so the leaderboard would cover only two of the three classes the brief names.

Proposed change. Extend the fetcher to retrieve the official game-level box score for every completed game, keyed to the official schedule, and store it as a game log with the game date and the source link.

Expected impact. Unlocks player-prop and prop-combination strategies and the prop correlation matrix, completing the strategy coverage the brief asks for.

Dependencies. Q-005Q-023Q-004

Decision paths

Path A Official box scores for every completed game (recommended)recommended

Fetch the official NFL.com box score for each game in the official schedule, parse the per-player lines into a game log, and key it by season, week and game.

  • Official source, and the only route to evaluating prop markets.
  • Enables the prop-combination correlation matrix the brief asks for.
  • Automatically extends to future seasons without new code.
  • A large number of pages, so the fetch window and rate limiting need care.
  • Parsing must be defensive: a layout change must degrade to a flagged gap rather than a wrong number.
Cost MediumEffort Weeks.Risk Medium - the main risk is silent parse drift, which the validator must catch by reconciling totals.Reversible Fully

Path B Official game books as PDFs

Parse the official game book PDF for each game instead.

  • The game book is the authoritative statistical record.
  • Includes starters, substitutions and inactive lists, which also serves the depth requirement.
  • PDF parsing is more brittle than HTML parsing.
  • Larger files and slower to fetch.
Cost MediumEffort Weeks.Risk Medium to high - PDF layout changes break extraction silently.Reversible Fully

Path C Restrict the competition to spread and total only

Drop player-prop classes and compete only on team markets using season and schedule data.

  • Uses only data already collected.
  • Fastest route to a working leaderboard.
  • Directly reduces the scope the brief asks for.
  • Prop markets are where most of the published public interest sits.
Cost LowEffort Days.Risk Medium - scope reduction rather than risk reduction.Reversible Fully

Recommendation

Path A satisfies the brief's three-class requirement from official sources and reuses the existing schedule-driven pipeline. Path B is more authoritative but more brittle; it can be added later for the depth fallback in S-009.

Evidence

S-014 Add week-over-week change views and a gap-filler for the site P1 Site & UX proposed

Problem. A static dashboard tells you the current state but not what changed since the last look. The owner's actual question on a Monday morning is 'what is different from last week', and answering it requires a second manual pass over two pages.

Proposed change. Store a weekly snapshot series and add (a) a change column on the injury and availability pages showing new, cleared and persisting entries, and (b) a 'what to check first' panel on the landing page that lists the largest week-over-week movements.

Expected impact. Turns the site from a reference into a daily working tool and enables out-of-sample validation on real snapshots.

Dependencies. Q-007Q-020

Decision paths

Path A Snapshot series with a diff view (recommended)recommended

Retain weekly snapshots, compute the difference between the current and previous snapshot, and surface new absences, cleared absences and status changes.

  • Directly serves the decision the owner actually makes.
  • Also creates the historical archive needed for an honest back-test (Q-007).

S-018 Constrain player-prop combinations by leg count and an independence test P1 Strategy Design proposed

Problem. Player-prop combinations are the most tempting way to manufacture a large number of apparent bets, and the most likely place for a player to be counted twice in the same parlay, which is a direct loss rather than a pricing question.

Proposed change. Cap the number of legs in a prop combination, prohibit the same player appearing in more than one leg, and require the legs' outcomes to be conditionally independent conditional on the game's pace and score state, with the independence assumption tested rather than assumed.

Expected impact. Makes the prop-combination class safe to compete in and prevents the most common silent loss.

Dependencies. Q-023Q-011

Decision paths

Path A Leg cap, player uniqueness and a conditional-independence check (recommended)recommended

A maximum leg count per class, a hard uniqueness rule per player, and a conditional-independence test on the leg signals given pace and scoring environment.

  • Removes the most common structural errors.
  • The conditional test catches the real correlation: two props in the same game are driven by the same game script.
  • The conditional-independence test needs enough games per prop type to have power.
  • Reduces the combinatorial space, which reduces the number of testable hypotheses, which is a feature under the hypothesis register (S-004).
