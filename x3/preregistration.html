Pre-registration

Seven registrations: what was frozen, when, and which ones fail their own gate

A registration is a date, a text and a window

Requirement R-09, R-66 and R-19. The brief's version of pre-registration is a commit hash that predates the evaluation window. This desk publishes the register with its date and window, and then says plainly which rows fail: every model row fails G-1, because the model entered the repository on the same day it was graded. Marking that honestly is worth more than a register that pretends otherwise.

What the register buys is the future: the corpus is frozen now, so every game from Week 11 onward is out-of-sample for this model. Suggestion S-09 proposes registering the next model before Week 12 so that the same thing is true for it from its first game.
