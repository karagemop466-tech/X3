Leaderboard

Ranked on a proper score; staking reported separately and never used to rank

Signal and staking are different columns, and only one can rank

Requirement R-05 and R-37: staking cannot promote a strategy. The rank key is the signal column, and the gate script asserts that no ordering reads a return. Every staking cell is blank because no price exists (F-01), so a lucky staking run cannot exist here at all — which is the strongest possible version of the requirement.

Controls come first. Three baselines are published before any strategy: the home club always (68/138), the better record (107/138, descriptive only because it uses post-game standings), and a coin flip. A strategy that cannot beat these is not a signal.

What would change our mind — both directions

  • S-01 (side) — would strengthen if a post-registration window reproduces a hit rate above 0.55 with n >= 200. Would collapse if that window returns to 0.50; the interval here already touches 0.50 at its lower edge, so this is not a remote possibility.
  • S-02 (total) — would strengthen if the model beat the benchmark MAE on a second window. Would be archived by D-2 if a second window is also adverse. Right now it loses on both Brier skill and MAE.
  • S-03 (combo) — would become rankable only with a validated joint probability and the operator's void/push rules. No amount of marginal evidence substitutes, because the legs are dependent — the observed joint rate is well below the product of the marginals.
  • The whole board — would change character entirely with a licensed price. Every ROI cell would fill, and the demotion gate D-1 would become triggerable.
