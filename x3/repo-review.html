What each earlier tree is good for, and what is wrong with it

Sixteen trees, one brief

The repository accumulated 16 parallel answer sets to the same brief across earlier sessions. None is deleted. This audit says what each is good for and what is wrong with it, so the reviewer can choose a canonical tree instead of reading sixteen.

The pattern that matters: the data is largely consistent where two sessions read the same official page twice, and the numbers computed on that data are not, because each tree wrote its own model. Three concrete data defects are published on the flagged page.

Line-by-line checks performed on the prior work

  • Injury row counts. Three different counts (254, 279, 345) appear for Week 10. Only 345 reproduces the live page row for row; the other two are stale captures, not different readings.
  • Standings. Two clubs (DET, NE) were stale in the committed file against the live page; corrected here and flagged (F-04).
  • Model spreads. One tree publishes the home spread with the sign of the expected margin instead of its negation, in 14 of 14 rows — the wrong side of the bet (F-17).
  • Week-11 injury page. One tree's capture lists reg11 as a separate 200 response at 413,311 bytes, identical to reg10. It is a redirect, not a report (F-02).
  • Live scores. One tree's results feed marks all 14 Week-10 games SCHEDULED; by 2026-11-15 two were final. Fixed here (F-03).
